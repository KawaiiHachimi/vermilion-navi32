## Fan chip

- `modprobe nct6775`: **`Found NCT6796D-S/NCT6799D-R or compatible chip at 0x2e:0x290`**, hwmon name `nct6799`.
  Unloaded again afterwards.
- Readings: `fan2` 1046 RPM (the only header with a fan seen turning; likely the CPU fan, unverified), `fan1` / `fan7`
  0 RPM; `pwm1` 86 %, `pwm2` 46 %; temperatures `SYSTIN` 40 C, `CPUTIN` 40.5 C, `TSI0_TEMP` 51.9 C (the CPU over TSI).
- Access path: the board ("ROG STRIX B650E-I GAMING WIFI") is in `nct6775`'s `asus_msi_boards` list, so Linux reads the
  chip through ASUS's ACPI WMI methods when the WMI device is present (it logs nothing either way). The firmware claims
  the chip's ports (`PNP0C02:03: Reserved [io 0x0290-0x029f]`).
- macOS: SMCSuperIO in the pinned VirtualSMC 1.3.8 knows the NCT6799D (added 1.3.2, fixed 1.3.3). It reads the ports
  directly, which is what the WMI path exists to avoid next to ACPI code that uses them too. On macOS nothing calls ASUS's
  WMI methods (no ASUS software), so a clash would need the firmware itself to touch the chip *(unverified)*.

## VRAM

- `VRAM: 24560M 0x0000008000000000 - 0x00000085FEFFFFFF`, BAR 32768M (Linux resizes the BAR; macOS keeps 256 MiB).
- `reserve 0x1300000 from 0x85fc000000 for PSP TMR`: VRAM offsets **24512 MiB - 24531 MiB**. DMUB is loaded through the
  PSP; its regions are ordinary amdgpu VRAM buffers (not fixed offsets), so nothing else fixed sits at the top.
- `amdgpu_vram_mm`: 24560 MiB total, 23720 MiB free at the desktop.

## UCLK under a VRAM load

`vkbench bandwidth 5 256`, buffers in memory type 0 (DEVICE_LOCAL, VRAM): **837.3 GB/s median**, 851.1 best.
`pp_dpm_mclk` every 0.5 s: 456 MHz at idle (one display, 240 Hz) -> **1249 MHz (top) within
0.5 s**, held the whole 5 s, 772 MHz right after. Levels: 96 / 456 / 772 / 1249. So the PMFW raises UCLK by itself for
VRAM traffic; macOS stayed at 96 under load only because its buffers are system memory (perf finding section 9).
