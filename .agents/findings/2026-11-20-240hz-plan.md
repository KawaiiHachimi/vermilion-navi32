# 240 Hz HDR on the XTX machine: what macOS needs (2026-11-20, from capture v2)

Inputs: [refresh-and-hdr findings](2026-11-19-refresh-and-hdr.md) ("240 Hz research", "Linux capture v2").

## The link: the existing trainer already speaks Linux's commands

Linux's 22 TRANSMITTER_CONTROL commands for 144 -> 240 equal what `PhxDpLink.h txCmd` builds for a connector with
phy 1 / hpdsel 3 (DP B), dword for dword: header `0x3c000180`; DISABLE `00000001 0 f4130003`; ENABLE `04000101 81000
f4000003`; SETUP_VSEMPH `04xx0b01 81000 f6130003` (xx = dplaneset). Only the symclk dword differs from HBR2 (54000).
The AUX side (DPCD 0x100/0x101/0x102/0x103-0x106, 0x120 FEC, 0x160 DSC) goes through the register AUX engine on
Linux 7.2 (no DMUB AUX), as in `PhxDpLink.h`. TPS4 for EQ is already there.

Changes the trainer needs (each a gate, not new behaviour):
- rate HBR3 (`0x1e`, symclk 81000) allowed;
- DP B as a connector (`{"DP-B", 1, 1, 2?, 2, 3}`: DIG1 / PHY B / HPD / AUX2 / hpdsel 3; the HPD index from the board
  table, unverified) only for the pipe-0 engine's retrain, never for the multiport probe;
- the sink caps from the extended block 0x2200 when 0x00E bit 7 is set (the LG says HBR2 at 0x001, HBR3 at 0x2201);
- the DMCUB gate takes `0x07008748` next to `0x07008742` (PCI rev 0xC8 only).

## The pipe: Linux's exact 240 Hz configuration, not a single pipe

A single pipe without DSC would need a DPPCLK hard minimum near 1.06 GHz, a DAL value Linux never sent on this card, and
HUBP values no capture has. Linux lights 240 Hz (8 and 10 bpc, SDR and HDR) only one way here: **HBR3 x4 + FEC + DSC
(16 bpp, 2 slices per half) + ODM 2:1** (OTG0 -> OPP0 + OPP1, HUBP0 + HUBP1 each scanning half of the same surface,
DSC0 + DSC1), 2 pixels per cycle, DISPCLK 537.5 MHz, DET 9/9/0/0. Every register value for it is in the 240 / 240-10 /
hdr-240 traces. So the 240 Hz plan follows that; 10 bpc / HDR at 240 is then the same plan with the 10 bpc DSC/PPS values.

Consequences on macOS:
- the flip path must write both HUBP0 and HUBP1 surface addresses (HUBP1 at viewport x 1280) at 240 Hz;
- pipe 1 (HUBP1 / DPP1 / MPCC1 / OPP1 / DSC1) must be free: refuse when OTG1 runs (the second-monitor case);
- the 2-pixel-per-cycle DTO convention (phase = pclk / 2) only for this plan.

## Order (one kext change per boot)

1. **D1 retrain at the same rate:** the pipe-0 engine retrains DP B HBR2 -> HBR2 at 1440p60 (stream off, TX DISABLE,
   ENABLE, CR + EQ, stream on). Proves TRANSMITTER_CONTROL on DMCUB `0x07008748` and the DP B gates with no new mode.
   Fall back: retrain again; last resort the next boot (the GOP relights 60 Hz).
2. **D2 HBR3 at 144:** same, at HBR3 with the 144 plan's timing (bandwidth headroom, no DSC): proves HBR3 on this PHY.
3. **E1 240 Hz SDR:** HBR3 + FEC + DSC + ODM 2:1 plan from the 240 trace; head-0 row 240; flip on both HUBPs.
4. **E2 HDR** (separately, also at 60-144): 10-bit surface + 10 bpc output + HDR infoframe + PQ; at 240 the 10 bpc PPS.
