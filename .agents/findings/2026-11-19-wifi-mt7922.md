# 2026-11-19: Wi-Fi on the XTX machine (MediaTek MT7922), AirportMtkWlan 2.1.6

## The card (Linux, read-only, 2026-11-19)

| | |
|---|---|
| Wi-Fi | `0b:00.0`, MediaTek MT7922 `14c3:0616` rev `0x00`, subsystem `105b:e0cd` (Foxconn), BAR 1 MiB + 32 KiB, MSI; Linux driver `mt7921e` |
| ACPI path | `\_SB_.PCI0.GPP7.UP00.DP58.EP00` (made unconditional by the DSDT NOP patches, `efi/machines/b650e-i-xtx.json`) |
| PCI path | root port `00:02.1` (`1022:14db`) > chipset switch `05:00.0` (`1022:43f4`) > downstream port `06:0b.0` (`1022:43f5`) > the card |
| Bluetooth | **USB `0489:e0e2`** ("MediaTek Inc. Wireless_Device", Foxconn vendor ID), bus 1 port 11, USB 2.0, three interfaces of class `e0`, Linux `btusb`. Earlier docs said `0e8d:0616`: that is wrong for this board |

## The kext: Arxusion/AirportMtkWlan v2.1.6, Tahoe build (research)

- `com.flxxxxddd.AirportMtkWlan` 2.1.6, x86_64, 2.7 MB with the firmware built in. It matches
  `0x061614c3` (IOPCIMatch) and links only Apple's families (IO80211Family, IOSkywalkFamily, corecapture,
  IONetworkingFamily, IOPCIFamily). **No Lilu dependency, no HeliPort-style app**: it is a native AirPort interface
  (the Wi-Fi menu, System Settings, Keychain auto-join).
- Needs `DisableIoMapper = true` (already on for Vermilion) and the native vendor ID (no SSDT hiding the card; we have
  none). README: `MinKernel 25.0.0`, `MaxKernel 25.99.99` for the Tahoe build, because the Sequoia build breaks
  `IO80211SkywalkInterface` vtables on Tahoe. `efi/build.py` now writes a kext's `max_kernel` from `components.json`.
- 2.1.6 is the maintainer's current pick: 2.2.0/2.2.1 (AWDL) panicked for users and were pulled (issue #15, comment
  2026-11-16). The README already describes 2.2.1; ignore that.
- 2.1.6 skips ASPM changes on AMD parent bridges (`parent_vendor == 0x1022`): an older version hard-froze an AMD
  machine as soon as DMA began (issue #11). All of this card's bridges are AMD.
- AWDL (AirDrop) and RSDB are off unless `-mtkawdl` / `-mtkrsdb` are set (2.1.6 release notes). Emergency boot-arg:
  `-mtkwlanoff`. Other boot-args: `mtk_cc=XX`, `-no160`, `-novht`, `-noht40`, `-nohe`, `-mtknoamsdu`,
  `-mtkallowaspm`, `-mtknoparentaspm`, `-mtkforceparentaspm`.
- Similar machines in the issues: #3 (ASUS B650E-F, MT7921K at the same kind of path behind GPP7, Tahoe 26.7.2:
  connection drops after minutes on v2.0.0, fixes in 2.1.0) and #5 (RZ616 `14c3:0616` behind GPP7, 26.7.2: scans and
  WPA2 failed on an old build, fixed in 2.1.0). Nobody has reported 2.1.6 on an RZ616 yet *(as of 2026-11-19)*.
- The kext can't touch the GPU, so hard rule 1 (SMU/PSP/DAL) doesn't apply. Card firmware: Linux's `mt7921e` loads it
  too, so the card is in a Linux state on a warm restart; the owner's cold power-off resets it anyway.

## The change (one EFI change for the next boot)

- The `vermilion` stage now inherits `base` (= `install` + AirportMtkWlan), so the booted EFI gets exactly one more
  kext. Built and checked 2026-11-19: `ocvalidate` clean; `diff -rq` against `/boot/EFI/OC`: only `config.plist` (one
  `Kernel > Add` entry, before AMFIPass, `MinKernel 25.0.0` / `MaxKernel 25.99.99`) and `Kexts/AirportMtkWlan.kext`;
  VermilionBoot byte-identical (b126). Installed 2026-11-19 06:14 with `efi/build.py install`; `OC.prev` = b126
  without Wi-Fi.
- A logger for the boot, readable from Linux: `tools/phxctl/wifilog.sh`, started by `run-once.sh` through
  `perflog_install.sh` (`PERF_NAME=wifi`, own launchd job), 20 min, one line a minute, to
  `/var/log/vermilion-wifi-<date>.log`: kext loaded, `AirportItlwm` count, Wi-Fi port, power, link, IPv4 yes/no;
  card fields from `system_profiler` and the driver's `MtkDebugLog` at the start and the end. MAC addresses masked,
  no SSID/BSSID/IP written by the script.
- Tested: `wifilog_test.sh` 6/6 and `perflog_test.sh` 10/10 on Linux and macbox; all mock suites green on macbox
  (`run.sh` 169/169, `b15test.sh` 159/159, `espflags_test.sh` 10/10, `recovery_install_test.sh` 6/6); the real
  logger as root under launchd on macbox (fake root, exit 0, nothing in `/Library/LaunchDaemons`), and the exact
  staged `run-once.sh`. The real run caught one bug the stubs missed: `ioclasscount` prints `<no such class>` instead
  of `0` on macOS 26 (fixed, stub updated).

## Rollback

From Linux: `sudo mv /boot/EFI/OC /boot/EFI/OC.wifi && sudo mv /boot/EFI/OC.prev /boot/EFI/OC`. If macOS hangs at
boot, power off; the default boot entry is Limine, so the next power-on lands in Linux.
