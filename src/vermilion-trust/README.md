# VermilionTrust.kext

A Lilu plugin that keeps AMFI's library validation **on** for the whole system and lets through only Vermilion's
own ad-hoc signed code, which every Metal process loads: `NVMTLDriver`, `libnvmtl_translate.dylib`, `libLLVM.dylib`,
`libzstd.1.dylib`, `libvulkan_radeon.dylib` (and the video decoder when it is installed). It is meant to replace
the boot-arg `amfi=0x80`. That boot-arg is AMFI's "allow everything": no library validation in any process, invalid
signatures accepted, third-party apps treated as platform binaries (no camera / microphone prompts), no FairPlay.
AMFIPass alone doesn't help here, because it only trusts code signed with Dortania's key. Background:
[`.agents/decisions.md`](../../.agents/decisions.md), 2026-11-22 "Security posture target = a real Mac".

## How it works

AMFI is a MAC policy. The kext finds it in `mac_policy_list` and swaps three pointers in its operation vector:
`mpo_file_check_library_validation` (dyld's `F_CHECK_LV`), `mpo_file_check_mmap` (executable mappings, including
dyld's `map_with_linking_np`) and `mpo_file_check_mmap_downgrade`. Each wrapper calls AMFI first. Only when AMFI
refuses (an error, or `PROT_EXEC` taken away) and the file's code directory hash is on the list compiled into the
kext does the wrapper allow it. All other decisions are AMFI's. Other MAC policies (Sandbox, ...) aren't touched.

The list is `phxtrust_list.inc`, generated by `gen_list.sh` from the installed files and compiled in. It can't be
changed on a running system. A new plugin, translator or RADV build has a new cdhash, so rebuild the kext
(`scripts/build/trust.sh`) and the EFI with every install of those. With `PHXTRUST_KEEP=1` the cdhashes already in
the list are kept (as `<name>-previous`), so one kext trusts the installed build and the next one: give the new file
as an argument, install the kext, and the plugin can be swapped before or after that boot. Without it the list is
exactly the files given.

Layouts come from XNU `xnu-12377.121.6`. On the XTX machine's kernel (26.7.1 25G241, `xnu-12377.161.15`) the vector
offsets `0x120` (mmap) and `0x200` (library validation), and `mpc_ops` at `0x20`, were read from the kernel's own
`mac_file_check_mmap` / `mac_file_check_library_validation`. `fg_data` at `0x38` was read from `fp_getfvp`.
At boot the kext checks that the slots are non-null and close to the vector before it writes anything.

## Boot-args and state

| Boot-arg | Effect |
|---|---|
| `-phxtrustoff` | the kext doesn't start |
| `-phxtrustlog` | also count every check of a listed file and record unlisted ad-hoc code (`CS_ADHOC`) mapped executable, in `debug.phxtrust_files` (for a boot that still has `amfi=0x80`, where AMFI refuses nothing) |
| `-phxtrustdbg` | Lilu debug output |

`sysctl debug.phxtrust_stat` gives the install state, the mode and the counters: library-validation calls and
refusals, executable mappings and refusals, overrides, refusals of unlisted code. `sysctl debug.phxtrust_files`
lists each listed file (checks in log mode, overrides, first process) and, in log mode, up to 32 unlisted ad-hoc
files mapped executable. Kernel log lines (`VermilionTrust:`, overrides only, at most 64 per boot) can be lost from
the message buffer early in boot: use the sysctls.

## Build

```sh
MKSDK=<MacKernelSDK> sh scripts/build/trust.sh      # fetches the pinned Lilu 1.7.2 DEBUG SDK, lists, builds, link gate
PATH=$HOME/.local/bin:$PATH python3 efi/build.py build --stage vermilion-trustlog
```

## Status

- 2026-11-22 23:31, 1.0.0, XTX machine, `vermilion-trustlog` (log only, `amfi=0x80` kept): loads, finds AMFI,
  installs; accelerated desktop unchanged. Two bugs found: it treated AMFI's normal removal of `PROT_EXEC` from the
  maximum protection of data mappings as a refusal (and undid it for listed files), and its ad-hoc filter used the
  platform flag, which `amfi=0x80` sets on everything.
- 2026-11-22 23:40, 1.0.1, log only: changes nothing (`overrides=0`); every load seen is a listed file; the only other
  ad-hoc code mapped executable is Apple's trust-cached dyld shared caches.
- 1.0.2: in enforce mode, `debug.phxtrust_files` also lists every unlisted file AMFI refused.
- 2026-11-22 23:45, 1.0.2, XTX machine, stage `vermilion-trust` (**`amfi=0x80` removed**): accelerated desktop as
  before. AMFI refuses the plugin ("mapping process is a platform binary, but mapped file is not") in WindowServer,
  Safari, Finder, SystemUIServer, Music, and the kext lets it through (`overrides=50`, `denied_unlisted=0`).
  Third-party apps lose `CS_PLATFORM_BINARY` (T3 Code `0x26014201` -> `0x22014201`).
- 1.0.3 (2026-11-23): same code; the list has 6 entries, the plugin with the Music readback fix and the previous
  plugin (`PHXTRUST_KEEP=1`).
